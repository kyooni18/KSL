# STS entry diagnostics — 2026-10-09

These artifacts investigate live yaw-to-roll response and whether kRPC can produce an original-STS aerodynamic wrench grid without advancing the loaded vessel. They are diagnostic only. None supplies a shadow-gate pass, qualified aerodynamic cells, or landing evidence.

## Yaw pulse and inertia

[`live-yaw-inertia-analysis.json`](live-yaw-inertia-analysis.json), reproduced by [`analyze_sts_yaw_inertia.py`](../../../Tools/analyze_sts_yaw_inertia.py), recomputes body-rate slopes from the repeated vacuum yaw pulse and compares them with a pure body-yaw torque counterfactual using the measured full-vessel and root-part inertia tensors. Pitch and roll commands remained zero, and the bench recorded SAS/RCS off, zero dynamic pressure, and zero thrust. The retained probe converts KRPC angular rates to degrees/s before storing `body_rates`; the analysis preserves that unit and also reports rad/s² equivalents.

The positive pulse measured +0.0695°/s² roll and +0.1805°/s² yaw; the negative pulse measured −0.0678°/s² roll and −0.1763°/s² yaw under the probe's command-aligned rate convention. The roll/yaw acceleration ratio is about 0.385 for both polarities. Inverting the symmetrized full-vessel inertia tensor for a unit body-z torque predicts about 0.036; the root-part tensor predicts 0.059. The full-vessel result is about 10.7 times smaller than the observed ratio, so off-diagonal inertia alone does not explain the measured vacuum cross-axis response. This result does not isolate the actuator source and says nothing about atmospheric yaw/roll coordination.

[`live-yaw-frame-crosscheck-20261009.json`](live-yaw-frame-crosscheck-20261009.json), produced by [`probe_sts_yaw_frame_crosscheck.py`](../../../Tools/probe_sts_yaw_frame_crosscheck.py), repeats the bounded yaw pulse from the verified full-mass checkpoint. It converts the measured non-rotating angular-velocity vector with `SpaceCenter.transform_direction` into the STS vessel frame. The native transform agrees with the quaternion basis calculation within 8.3e−9 rad/s. A first trial using `Vessel.angular_velocity(vessel.reference_frame)` returned zero throughout because that target frame co-rotates; it is retained as [`live-yaw-reference-frame-caveat-20261009.json`](live-yaw-reference-frame-caveat-20261009.json) and excluded from inference. The vessel-frame axis definitions and tensor frame are documented in the [kRPC Vessel API](https://krpc.github.io/krpc/0.6.0/python/api/space-center/vessel.html); vector conversion is documented in the [kRPC SpaceCenter API](https://krpc.github.io/krpc/0.6.0/python/api/space-center/space-center.html).

The corrected right-handed rate readback gives absolute roll/yaw acceleration ratios of 0.375 and 0.383 for positive and negative yaw commands. The independently measured tensor predicts 0.036 for a pure yaw-axis torque, still about 10.5 times smaller. The earlier `body_rates` helper negates the native vector, which reverses signed acceleration and torque components but leaves the ratios unchanged. Applying Euler's equation to the native rates infers approximately −95/−3,150 N·m roll/yaw moments for the positive command and +94/+3,043 N·m for the negative command. Those moments are derived from rates and inertia, not measured directly at the wheel; the source remains unresolved. The vacuum pulse provides no atmospheric coordination evidence.

The original three-axis torque inference applied Euler's relation, including the small gyroscopic term, to the earlier pulse. With pitch and roll commands zero, it inferred about 3.1% roll-axis moment relative to yaw-axis moment. The corrected native-frame analysis preserves that magnitude ratio and fixes the signed interpretation. This is inferred net torque, not a direct actuator telemetry measurement or qualification result.

## kRPC aerodynamic wrench grid

[`live-aerodynamic-wrench-grid.json`](live-aerodynamic-wrench-grid.json) evaluates 240 hypothetical states using `Flight.simulate_aerodynamic_wrench_at` on the loaded original STS. The grid varies Mach, angle of attack, sideslip, and bank while holding the directly measured live position and UT fixed. Each simulated velocity includes the body's rotational surface velocity so the requested Mach and air-relative angles match the intended values. The existing vessel, control surfaces, and action-group state supply the aerodynamic model; the probe issues no control or vessel-state setters.

At the captured state, the force and torque parity checks against live telemetry differed by 0.41% and 0.42%. The grid's achieved angle errors were below 0.00002 degrees. The live state remained paused and unchanged, and the named checkpoint hash remained `bb27c762add826731df3ad57332efd77d3d3a5d0928caa2ca361907ae0b1703f`.

This validates the API as a way to query counterfactual wrench values for the original vessel while preserving explicit input and checkpoint provenance. The retained grid is still only an upper-atmosphere slice at one position/UT (62.8 km, about 3.7–47.1 Pa). It is not a measured flight envelope or a lower-atmosphere certification set. A useful envelope needs additional altitude/UT slices and uncertainty checks against later live measurements; every simulated sample must remain labeled as unqualified diagnostic data.
