Exact search gate diagnosis
At UT 196420.528797551 (+415.36 s), all inTerminalSearchEnvelope gates passed:
- ASL altitude 25208.363 <= 30000 + 225.644598*5 = 31128.223 m.
- ASL altitude 25208.363 >= min(22000, HAC exit height) = 3505.548 m.
- Mach 2.949768 <= 2.5 + 0.35 + 0.1 = 2.95.
- Airspeed 892.924622 <= fallback terminalPlanningMaximumSpeed 1300 m/s.
There was no MM305Admission rejection: no terminal result was delivered and
that gate was never called. The last recorded entry proposal epoch was
UT 196155.508797690, about 265 s before terminal search eligibility.

The actual blocker was the single planning worker: EntryCaptureForecaster's
continuation while loop omitted Task.isCancelled. A canceled predict() returns
without advancing simulated time, so the outer loop could repeat forever.
Dynamics revisions cancel in-flight planning, exposing this nonprogress loop.
The existing runtime then refused all new planning requests while that task
remained outstanding. Cancellation plus a time-progress guard fixes this.
Terminal requests also preempt entry work and return without waiting for a
second MM304 solve; search arming is latched until a plan is accepted.

a70729c: aerodynamic trim must not veto RCS-controlled entry AoA.

AoA shaping uses tau = measured FCS pitchResponseSeconds /
(1 - GuidanceTargetLimiter.responseReserve), an exponential monotone filter,
then the existing command slew and target limiter. The existing limiter's
no-overshoot step and vehicle maximumBank clamp remain unchanged.
The aerodynamic-only AoA ceiling uses identified trim/configuration; RCS-enabled
entry may use the vehicle maximum AoA. RCS remains an attitude actuator,
not a reason to reject a flight.
