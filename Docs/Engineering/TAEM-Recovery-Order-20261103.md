# Comparable terminal recovery outcomes

This checkpoint implements a prerequisite from the replacement research: an incomplete terminal tail must not win by avoiding the cost of the missing flight. It does not implement the proposed topology-seeded command search or establish flight readiness.

Terminal evaluations now retain a comparison context: the original command-history seed identity, complete initial state and mission configuration, atmosphere and aerodynamic model instance identities, and continuation policy. Branch continuation preserves the seed identity. Runtime UUIDs identify shared model instances; they are not archived model provenance, empirical validation, or resource hashes. Missing legacy context is unassessed; mismatched contexts cannot be ranked together.

The recovery comparator checks finite accounting and terminal endpoint consistency before treating an evaluation as complete. A valid complete outcome outranks an incomplete or invalid one. A qualified outcome outranks a failed outcome; among qualified outcomes, shorter elapsed flight wins. Among failed outcomes, comparison is deliberately partial: two otherwise accepted touchdown and sustained runway-stop outcomes can be ordered when one has no greater peak or accumulated pressure/load excess in every dimension and improves at least one. Tradeoffs, crashes, misses, other failures, and unknown tails retain the incumbent. No invented weighted crash/miss price is introduced. This is not the report's complete all-bad recovery policy.

The existing HAC qualifier now evaluates its eligible candidates from one shared seed and uses that comparator instead of replacing the incumbent merely because a result reports `feasible`. Its existing geometric eligibility filter and first-qualified early exit remain. The result does not expose all rejected alternatives or their comparison reasons. Candidate identifiers still identify the planning family, not individual trials. MM305 control ownership and its acquisition/spiral implementation are unchanged.

The shared target limiter also clamps requested incidence to the existing configured minimum and maximum before slew limiting, with an endpoint guard for inherited history. Configured bank protection remains in place. This does not increase physical limits; in-range requests retain their behavior.
