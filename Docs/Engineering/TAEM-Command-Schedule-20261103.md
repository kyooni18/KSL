# Native command-schedule evaluation primitive

`TAEMCommandScheduleEvaluator` evaluates explicit acquisition/heading-alignment target segments through `NativeCommandRollout`. Each segment supplies its command and duration in seconds. The target limiter, controller, actuator response, trim history, angular rates, achieved attitude and translation continue across segment boundaries. No attitude or spatial reference is assigned directly. The result contains actual propagated steps (requested, limited, issued, before/after states), traveled chord distance, continuation seed, moment-support status and endpoint reason.

This is the rollout primitive required by the research's proposed shooting search. It does not yet generate direct/turn/winding/return/reversal topologies, optimize their parameters, regenerate a spiral, rank terminal outcomes, or change MM305 control ownership. No new runtime caller is enabled. A schedule-exhausted endpoint is only an evaluated prefix, never a priced terminal recovery or a qualification.

Input validation rejects nonpositive/nonfinite segment duration, nonfinite targets, non-TAEM phases and invalid integration/coverage settings before branch propagation. Out-of-envelope finite targets still pass through the shared configured target limiter; requested and issued commands remain distinct. Segments end on their exact requested duration; a fractional last control tick is supported.

Configured prediction duration and path length are search coverage, not physical limits. Duration coverage is enforced by shortening the final step. Path coverage uses accumulated displacement chords and is checked at command boundaries; the reported distance can exceed coverage by the last command step. It is not an exact continuous arc-length bound or a physical infeasibility conclusion. Cancellation and contact are also explicit prefix endpoints.

The evaluator checks the original moment evidence before and after every control step and stops when unsupported. The step crossing the evidence boundary remains recorded and the endpoint is unsupported, not a successful schedule. This preserves the known control-step sampling limitation; it does not assert continuous model support inside a step. Inconsistent continuation models are rejected. Controller/plant errors return the partial extent and diagnostic. Retaining a seed does not refresh measured evidence.

TerminalTrajectoryEvaluator now accepts an exhausted command prefix and continues its native seed using the same model/configuration. Shared NativeTrajectoryAccounting carries aerodynamic work, pressure/load peaks and integrals through the join. Elapsed time, energy and height changes are measured from the prefix origin, and the original comparison context is retained. The prediction horizon is shared across prefix and suffix rather than restarted at the join. Prefixes with a non-exhausted endpoint, a mismatched model/configuration/policy, or an initial-state mismatch are invalid for this continuation path. Prefix contact remains a separate endpoint; it is not admitted through this exhausted-airborne-prefix API. Comparing only terminal tails starting at different join states would violate the common-start contract. The prefix alone still cannot enter TerminalRecoveryOrder as a complete outcome.
